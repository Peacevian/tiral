## 1. What the game is (Phase 1 summary)

| Layer | Implementation |
|---|---|
| Framework | Next.js 15.5 app router, React 19, TypeScript, pnpm monorepo |
| Styling | Tailwind 3 + `app/globals.css`; `next/font` on landing |
| Map | MapLibre GL 5, OpenFreeMap `positron` vector style (55 layers) |
| 3D | three 0.170 + @react-three/fiber 9 + drei 10. A full-screen transparent R3F `<Canvas>` overlays the map (`components/ThreeLayer.tsx`), camera copied from `map.transform` each frame. Standalone canvases for house, bike, rolex stall, car wash, landing runner |
| Assets | `public/models/runner.glb` (1.43 MB, rigged, 24 clips), canvas-generated textures, road snapshot `packages/road-graph/src/kampala-roads.json` |
| Multiplayer | Colyseus 0.18. Race/Hustle/Stall rooms tick with `setInterval(100ms)`; hand-rolled messages (no Schema). Server-authoritative movement on the road graph; client sends only inputs |
| Client loop | `lib/useRoadMovement.ts` rAF loop predicts local position (dt-scaled) and reconciles to server snaps > 12 m; remote avatars lerp per frame in `Avatar3D` |
| State | One `useColyseus()` hook exposed as a single context in the root layout; `lib/player.tsx` polls `/api/player` every 60 s |
| Physics | None (kinematic on road graph) |
| Economy | Server computes payouts; idempotent ledger with daily caps |

**Player flow:** `/` → "Run for it" → `/play` sign-in gate (TikTok / guest) → 3-step intro → Hub → Quick race → lobby → set start pin → start (usually solo) → race → results. Hustles: Hub → `/hustle?gig=…`.

## 3. Findings

### P0 — Critical

**P0-1 ✅ Anyone can fire mobile-money payment prompts at any phone number**
- **Where:** `app/api/billboards/purchase/route.ts:36-106` → `lib/relworx.ts:47`
- **Evidence:** no session check; `msisdn` taken straight from the request body; no rate limit. Each call also inserts a `billboard_campaigns` row.
- **Effect:** harassment vector against arbitrary Ugandan numbers; exhausts Relworx's own rate limit (the code already handles `/rate-limit|5 requests/`, l.111) so real buyers are blocked; DB spam.
- **Fix:** require a session; nginx `limit_req` on `/api/billboards/`; DB check of max N pending per number per hour; optional CAPTCHA before prompting.
- **Risk / effort:** low / S · **Verify:** anonymous call → 401; second call within window → 429.

**P0-2 ✅ Landing, /advertise, /privacy, /terms cannot scroll**
- **Where:** `app/globals.css:5-19` sets `overflow:hidden` + `height:100dvh` on `html, body`; these pages use `min-h-screen` mains that never become scroll containers (`app/page.tsx:20`, `advertise/page.tsx:127`, `privacy/page.tsx:11`, `terms/page.tsx:11`).
- **Evidence:** at 375×812 landing `body.scrollHeight` = 1984 with `overflowY: hidden`; wheel scroll leaves `scrollTop` at 0. `/advertise` 999 vs 812.
- **Effect:** everything below the hero is unreachable. On phones the advertiser **Pay** button is off-screen (revenue blocker). Privacy/Terms are cut off.
- **Fix:** give each document page `h-dvh overflow-y-auto` (the pattern `leaderboard/page.tsx:46` already uses), or scope the lock to game routes only.
- **Risk / effort:** low / S · **Verify:** scroll each page at 375×667 and 1280×720.

**P0-3 ✅ Rolex stall leaks a GPU texture every 80 ms**
- **Where:** `components/hustle/StallScreen.tsx:576` (`useTicker(80)`) → `components/rolex/RolexStall3D.tsx:184` `useStripes([...inline array...])` → `useMemo(..., [colors])` (l.60-76)
- **Evidence:** a new array literal every render invalidates the memo and creates a new 256×8 `CanvasTexture`, which is never disposed.
- **Effect:** ~750 textures/min (~3,750 in a 5-min shift), a GPU upload every tick, and a full stall-scene React reconcile at 12.5 Hz. Likely crash or jank on low-end Android.
- **Fix:** hoist the colour array to module scope; dispose in effect cleanup; move the ticker into the HUD timer only; `memo` the 3D scene.
- **Risk / effort:** low / S · **Verify:** `renderer.info.memory.textures` stays flat over 30 s.

**P0-4 ✅ Whole game page re-renders every animation frame while moving**
- **Where:** `lib/useRoadMovement.ts:154-156` calls `setPosition(next)` inside the rAF tick; consumed at the page root (`app/play/page.tsx:229`, `app/hustle/page.tsx:182`)
- **Evidence:** also cascades into:
  - `useRaceCamera` follow effect (P1-2)
  - `StartPins` / `HustlePins` effects with no deps (`StartPins.tsx:59-94`)
  - `useRoadMovement` keyboard listeners re-registered each render (l.168-191)
  - `classifyConnectedEdges` in a per-frame `useMemo` (l.273-276)
  - every `Avatar3D` / `RealisticAvatar` subtree
- **Effect:** React reconciliation of the whole game UI and all avatars at 60–120 Hz. This is the largest CPU/battery cost on phones and the main source of frame drops while walking.
- **Fix:** keep predicted position in a ref or small external store; self avatar reads it in `useFrame`; push React state only on edge change/stop/turn plus a 5–10 Hz throttled value for HUD and camera; `memo` `Avatar3D`, `ControlDeck`, `TopBar`.
- **Risk / effort:** medium / M · **Verify:** React Profiler commits/sec while holding W; Performance-panel scripting ms per frame.

**P0-5 ✅ Billboard webhook signature check is off in production right now** (escalates P1-13)
- **Where:** `lib/relworx.ts:145` `if (!key) return true`; `api/billboards/relworx/route.ts:25-44`
- **Evidence:** on 15 Oct `RELWORX_WEBHOOK_KEY` is not set in `/opt/tiral/web.env` (checked for presence only, no value read). The handler re-checks whatever `internal_reference` the body supplies and activates the campaign named by `customer_reference`, without comparing amount or stored reference.
- **Effect:** anyone holding one successful internal reference (e.g. from their own 1-slot payment) can activate any pending campaign, including larger ones. Real-money integrity issue.
- **Fix:** set the key; fail closed when it is missing and `NODE_ENV=production`; then the P1-12/P1-13 binding (store the reference, match reference and amount).
- **Risk / effort:** low / S · **Verify:** unsigned webhook → 401; forged reference pair → campaign stays pending.
